# Atlas: brand

## Name

**Atlas.** An atlas is a book of maps. This repository holds one map: what an agent entity needs, drawn in five
layers (the entity itself, how it meets the world, how it stays trusted and running, the business around it, and
the compute below it). Each category is a region of the map, each component a feature on it, and each element one
decision you make there. One word, a familiar object, and the job in it: show the whole ground before anyone builds
on it.

The repository is `agent-entity`, the list is the Agent Entity Checklist, and Atlas is its keeper.

## Tagline

> **Every question an agent entity must answer, with a default for each.**

"Every question" is the 16 categories, which do not change with what the entity becomes. "A default for each" is
the pick in every row: what an entity gets when nobody chooses, with the reason.

## Symbolic connection to the work

| Brand element             | What it maps to in the list                                                      |
| ------------------------- | -------------------------------------------------------------------------------- |
| An atlas, a book of maps  | The map: 16 categories in 5 layers                                               |
| A region on each page     | A category: one question every entity must answer                               |
| The legend                | How to read a row: open source, closed source, the pick, the routes, the score  |
| The date a map was drawn  | The `read` date on every product: evidence ages and must be read again          |

## Landing copy

Building an agent entity means answering the same questions every time: what it thinks with, what it is made of,
where people reach it, why anyone can trust it, how it is kept running, how it earns and who stands behind it. This
checklist puts every one of those questions on one page, splits each into single decisions, and gives each decision
a default with a reason. Agents read the same list as JSON.
